DWARF — cardano-node vs Amaru Long-Range Deep-Rollback Differential

Cross-implementation consensus safety test on the upstream cardano_amaru mesh · chain-serving adversary + eclipse · repeating soak · generated 2026-07-16
The core long-range safety rule in Ouroboros: an honest, already-synced node must never roll back more than the security parameter k (here k=5) — even when told to by its only source of the chain. Accepting a deeper rollback abandons settled history. DWARF eclipses each node behind a chain-serving adversary that, once the node is caught up to the real tip, injects a rollback 10 blocks deep (> k). The differential question: does the new Amaru node enforce the k-bound identically to cardano-node? Across a repeating soak of 91–92 injections per implementation, both refused every time. Zero divergences.
Substrate. The real upstream cardano_amaru topology (k=5, epoch 125 slots, active-slot-coeff 0.2, Conway at epoch 0). Each target node is isolated on its own bridge network so its only upstream peer is a dwarf-adversary chain-serving instance, which sources the real honest chain from producer p1 and re-serves it. cardano-node target: a fresh eclipsed relay-lr. Amaru target: amaru-lr, seeded from an already-synced Amaru database so it starts at the tip — a long-range attack targets a running, synced node.

Oracle: per target, the selected tip must never regress more than k below the maximum height it reached after an injection. A regression > k = accepted deep rollback = safety violation. Neither implementation regressed on any cycle.

Method

Eclipse: the node under test reaches ONLY the adversary (a true eclipse — its topology / --peer-address lists the adversary alone). Adversary: dwarf-adversary --protocol blockfetch --upstream p1.example:3001 --mutation-rate 0 serves the real chain so the node stays caught up. Stimulus: deepRollbackChainSyncServer — once the node is at the honest tip (--rollback-min-tip), inject one MsgRollBackward exactly --rollback-depth 10 blocks behind the head (> k), then resume serving; --rollback-repeat-secs 120 re-arms it every 2 min for the soak. A regression monitor samples both nodes' tips continuously and alerts on any > k drop.

Amaru note

Amaru is seeded from an already-synced database rather than cold-synced through the adversary. This is deliberate and faithful to the threat model (the victim of a long-range attack is a running, synced node). It also sidesteps an orthogonal issue: cold-syncing Amaru through the adversary fails on header validation, because Amaru's header check requires per-epoch stake distributions that its ledger has not yet computed during bulk sync — unrelated to the rollback property under test.

Bottom line

On the deep-rollback regime, the new Amaru node enforces the k-rollback safety bound exactly as cardano-node does — a positive consensus-equivalence result on a from-scratch reimplementation. A divergence would have been a genuine finding; identical safe behavior is the reassuring one, and the harness is now a repeatable soak that would catch a future regression in either implementation. Scope: this is the deep-rollback rejection variant; the heavier costless-simulation long-range attack (forging a longer valid chain to exercise Genesis density-based selection) is the follow-on.
