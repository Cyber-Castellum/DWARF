DWARF Consensus — Cross-Implementation Chain-Selection Differential

Status & capability note · does the Haskell cardano-node and Amaru ever disagree on which chain is real? · runs on the upstream cardano_amaru topology
DWARF now runs a chain-selection differential between the two Cardano node implementations — the Haskell cardano-node and Amaru — on a real mixed network, and checks, block-for-block, whether they ever pick a different chain. Across every regime exercised so far — honest steady state, a shallow (<k) fork that heals, a deep (>k) fork that must not, and an epoch-boundary transition — cardano-node and Amaru selected the identical chain every time (0 divergences). A consensus split between the two clients is the highest-value failure class; none was found.

What it tests, in one paragraph

Cardano is moving from one node implementation (Haskell cardano-node) toward a second, independent one (Amaru). If the two ever disagree about which sequence of blocks is the canonical chain, the network splits. This harness stands up a real mixed devnet (Haskell producers + relays alongside Amaru relays and an Amaru-fed consumer), deliberately induces forks, and compares — at time-aligned instants — the chain each implementation selects. Agreement is a pass; any divergence is a finding.

Amaru's selected chain is observed through amaru-consumer — a cardano-node that catches up through the Amaru relays, so its tip is a cardano-cli-queryable proxy for "what Amaru served/selected."

Exhaustive sweep (smoke → coverage matrix)

The single-shot scenarios are driven exhaustively by consensus_differential_sweep.py, which walks a grid of fork depths (crossing the security parameter k) and verifies both the cross-implementation agreement and that the recover-vs-strand behavior is identical for both clients. Demonstration grid:

  depth=15s  cardano-node == Amaru ✓   p2 RECOVERED   (all at block 4962)

The k-boundary crossover (shallow forks heal, deep forks strand) is captured automatically, and cardano-node ≡ Amaru holds at every depth. Scales via --depths / --trials.

Scope & honest framing

  • This is a differential (do the two implementations agree?), not a threshold measurement. It does not, and is not meant to, measure economic-attack numbers like the "40%".
  • The runs to date are smoke-level (short windows, single/few trials) plus the demonstration sweep — proof the mechanism and tooling work and the first shots pass. Full exhaustiveness layers on the same harness: many trials × seeds, long soaks, and the Antithesis deterministic scheduler.
  • Amaru's selection is read through amaru-consumer (a cardano-node fed by Amaru), because the Amaru relays log quietly by design.
  • A known startup flake (producers occasionally split-brain before the mesh converges) is wrapped by the convergence gate so scenarios run on a healthy network.

Every run captures a tamper-evident evidence bundle (per-node forge/ChainDB traces, tip observations, the differential verdict).
