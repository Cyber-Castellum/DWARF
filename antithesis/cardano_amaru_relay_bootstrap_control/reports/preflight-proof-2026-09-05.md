## Setup-marker boundary

The current supplier contract requires each relay to write an early deployment
marker before its long bootstrap. The sidecar's `setup_complete` therefore
means deployment acceptance, not bootstrap, participation, or consumer
convergence. This control never uses that marker as its success result; the
separate runtime probe supplies those stronger gates.

For the later Antithesis security package, this distinction must be explicit in
SDK properties and first-timeline triage: setup acceptance plus reachable
bootstrap completion, two advancing relays, consumer-through-Amaru progress,
driver invocation, both target observations, and actual adversarial encounters.
